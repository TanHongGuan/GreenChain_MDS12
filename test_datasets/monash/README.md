# Monash University Malaysia test workbooks

**Synthetic data.** These are not real meter readings, bills or emissions statements for
Monash University Malaysia or any of its buildings. Every figure is generated by
[`generate.py`](generate.py) from a fixed seed, and each workbook repeats the warning on its own
`00_Read_Me` sheet. The campus and buildings are named so the files read like something an
uploader would recognise — nothing in them should ever be quoted as fact.

Regenerate with `python test_datasets/monash/generate.py`. The seed is fixed, so the files are
reproducible; `backend/app/tests/test_monash_datasets.py` checks each one still imports to the
totals in [`expected/`](expected).

## The files

### Engineering Building

| File | Period | Purpose |
|---|---|---|

| `MUM_ENG_2026_Q1_UNREVIEWED.xlsx` | 2026-Q1 | Upload second, **leave unreviewed** |
| `MUM_ENG_2026_Q1_INVALID.xlsx` | 2026-Q1 | Must be **refused** — never published |
| `MUM_ENG_2026_Q2_VALID.xlsx` | 2026-Q2 | |
| `MUM_ENG_2026_Q3_VALID.xlsx` | 2026-Q3 | |
| `MUM_ENG_2026_Q4_VALID.xlsx` | 2026-Q4 | |

The approved Q1 file plus Q2–Q4 make a complete 2026 for the building. The unreviewed and invalid
files are extras on top of that year, both for Q1.

The two Q1 submissions are not copies: the second is the same quarter re-read after a billing
query, so its figures differ slightly. Approving one and leaving the other pending is what gives
the chart's approved / unreviewed / both filter something to show.

### Pharmacy Building

`MUM_PHA_2026_Q1_VALID.xlsx` … `Q4`, one per quarter, all valid.

## Why the two buildings look different

A real platform receives whatever the producer wrote. These two are deliberately unalike, and
between them they exercise every conversion and date rule the importer has:

| | Engineering | Pharmacy |
|---|---|---|
| electricity | daily kWh, `DD/MM/YYYY` | daily MWh, `MM/DD/YYYY` |
| water | cumulative m³, `YYYY-MM-DD` | daily litres, `YYYY/MM/DD` |
| carbon | monthly tCO₂e, `YYYY-MM` | monthly kgCO₂e, `YYYY-MM` |
| aggregation | sum daily, difference cumulative, monthly | sum daily, sum daily, monthly |

Engineering's electricity sheet also carries a **chiller plant submeter**, which is a share of the
main supply and must never be added to it. Its water meter is cumulative and runs continuously
across the year, so each quarter opens on the reading the previous one closed with — the opening
figure is stated on each file's `Meter_And_ETL_Rules` sheet.

Pharmacy's electricity dates are month-first (`01/13/2026`), which the importer resolves from the
column itself rather than from any convention.

## Planted faults

`MUM_ENG_2026_Q1_INVALID.xlsx` contains three, listed in
`expected/MUM_ENG_2026_Q1_INVALID_expected_errors.csv`. All three are reported together in one
refusal:

| sheet | date | fault |
|---|---|---|
| `Electricity_Daily` | 2026-01-19 | `N/A` where a reading belongs — `INVALID_NUMERIC` |
| `Electricity_Daily` | 2026-02-16 | reading left blank — `MISSING_VALUE` |
| `Water_Meter` | 2026-02-09 | cumulative meter falls 86.40 m³ — `DECREASING_CUMULATIVE` |

## Suggested upload order

1. Create both buildings under **Monash University Malaysia**.
2. Engineering Q1 approved file → approve it as the auditor.
3. Engineering Q1 unreviewed file → leave it.
4. Engineering Q1 invalid file → confirm it is refused and that all three faults are named at once.
5. Engineering Q2, Q3, Q4.
6. Pharmacy Q1–Q4.

Engineering's water needs its opening reading entered at the mapping step; the value is on each
file's rules sheet.
