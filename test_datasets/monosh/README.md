# Monosh — test workbooks

**Synthetic data.** Monosh is an invented organisation. Nothing in these files is a real meter
reading, bill or emissions statement for any company. Every figure is generated by
[`../generate_company_datasets.py`](../generate_company_datasets.py) from a fixed seed, and each
workbook repeats the warning on its own `00_Read_Me` sheet.

Upload these with the **monosh@greenchain.test** account.

## Files

| Building | Files | How it is written |
|---|---|---|
| Monosh Science Building | `MONOSH_SCIENCE_2026_Q1` … `Q4` | daily kWh, `YYYY-MM-DD` · cumulative m³, `DD/MM/YYYY` · monthly tCO₂e |
| Monosh Library | `MONOSH_LIBRARY_2026_Q1` … `Q4` | **monthly** kWh, m³ and tCO₂e — one row per month, nothing to aggregate |

Eight workbooks: two buildings, four quarters of 2026 each. All valid — there are no planted
faults in this set.

[`expected/`](expected) holds the quarterly totals each file should produce, so a run can be
checked rather than eyeballed.

## Things that need a decision at the mapping step

**Monosh Science Building's water meter is cumulative.** A month's usage is the rise across it, so the first month of
each quarter needs the reading from before that quarter. It is on every file's
`Meter_And_ETL_Rules` sheet; Q1 opens at **57410.80**. The meter runs continuously through the year,
so each quarter opens exactly where the previous one closed.

**Submeters must not be added to their parent.** Monosh Science Building reports a submeter beside its main supply,
and the main supply already includes it. The rules sheet says so, and the mapping step names the
other numeric columns on that worksheet when you open the metric.

**Dates are not all written the same way.** Each sheet states its own format on the rules sheet;
the importer works the order out from the column's own values.

## Rolling reporting year, 2025-Q4 to 2026-Q3

A third building covering four consecutive quarters that cross the calendar boundary, generated by
[`../generate_rolling_year.py`](../generate_rolling_year.py).

| Building | Files | How it is written |
|---|---|---|
| Monosh Engineering Hall | `MONOSH_ENGINEERING_2025_Q4`, `MONOSH_ENGINEERING_2026_Q1` … `Q3` | daily kWh, `YYYY-MM-DD` · cumulative m³, `YYYY-MM-DD` · monthly tCO₂e |

Its water meter is cumulative and runs continuously through the reporting year, so each
quarter opens on the reading the previous one closed with — including across the calendar-year
boundary. Q4 2025 opens at **63480.20**, and every file states its own opening reading on its
`Meter_And_ETL_Rules` sheet. Its workshop submeter is a share of the main supply.

### The invalid file

`MONOSH_ENGINEERING_2026_Q3_INVALID.xlsx` must be **refused**, never published. It carries three
faults, listed in `expected/MONOSH_ENGINEERING_2026_Q3_INVALID_expected_errors.csv`, and all three
come back in a single refusal:

| sheet | date | fault |
|---|---|---|
| `Power_Log` | 2026-07-16 | `NO READING` where a figure belongs — `INVALID_NUMERIC` |
| `Power_Log` | 2026-08-23 | reading left blank — `MISSING_VALUE` |
| `Water_Meter` | 2026-08-02 | cumulative meter falls 112.80 m³ — `DECREASING_CUMULATIVE` |
