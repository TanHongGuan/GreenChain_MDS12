# Sonwoy — test workbooks

**Synthetic data.** Sonwoy is an invented organisation. Nothing in these files is a real meter
reading, bill or emissions statement for any company. Every figure is generated by
[`../generate_company_datasets.py`](../generate_company_datasets.py) from a fixed seed, and each
workbook repeats the warning on its own `00_Read_Me` sheet.

Upload these with the **sonwoy@greenchain.test** account.

## Files

| Building | Files | How it is written |
|---|---|---|
| Sonwoy Corporate Tower | `SONWOY_TOWER_2026_Q1` … `Q4` | daily kWh, `DD/MM/YYYY` · cumulative m³, `YYYY-MM-DD` · monthly tCO₂e |
| Sonwoy Logistics Hub | `SONWOY_HUB_2026_Q1` … `Q4` | daily **MWh**, `MM/DD/YYYY` · daily **litres**, `YYYY/MM/DD` · monthly **kgCO₂e` |

Eight workbooks: two buildings, four quarters of 2026 each. All valid — there are no planted
faults in this set.

[`expected/`](expected) holds the quarterly totals each file should produce, so a run can be
checked rather than eyeballed.

## Things that need a decision at the mapping step

**Sonwoy Corporate Tower's water meter is cumulative.** A month's usage is the rise across it, so the first month of
each quarter needs the reading from before that quarter. It is on every file's
`Meter_And_ETL_Rules` sheet; Q1 opens at **18260.40**. The meter runs continuously through the year,
so each quarter opens exactly where the previous one closed.

**Submeters must not be added to their parent.** Sonwoy Corporate Tower reports a submeter beside its main supply,
and the main supply already includes it. The rules sheet says so, and the mapping step names the
other numeric columns on that worksheet when you open the metric.

**Dates are not all written the same way.** Each sheet states its own format on the rules sheet;
the importer works the order out from the column's own values.

## Rolling reporting year, 2025-Q4 to 2026-Q3

A third building covering four consecutive quarters that cross the calendar boundary, generated by
[`../generate_rolling_year.py`](../generate_rolling_year.py).

| Building | Files | How it is written |
|---|---|---|
| Sonwoy Riverside Office | `SONWOY_RIVERSIDE_2025_Q4`, `SONWOY_RIVERSIDE_2026_Q1` … `Q3` | daily kWh, `DD/MM/YYYY` · daily m³, `DD/MM/YYYY` · monthly tCO₂e |

Its water is daily consumption, not a meter reading, so no opening reading is needed. Its
car park submeter is a share of the building intake and must not be added to it.

## The workbooks are not in git

Only the generator and the expected-totals CSVs are tracked. Rebuild the `.xlsx` files with:

```bash
python test_datasets/generate_company_datasets.py   # the 2026 sets
cd test_datasets && python generate_rolling_year.py # 2025-Q4 to 2026-Q3
```

The seed is fixed, so every cell comes back identical and the expected files still verify. Only
`docProps/core.xml` differs between runs, because openpyxl stamps the creation time.
